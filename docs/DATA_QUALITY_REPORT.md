## 검사 내용과 문제 유형

- 모든 MAT의 읽기, signals/fs 필수 항목, 실수 수치 배열, 예상 형태 `(6, 65536)`, fs=25,600Hz 확인
- 전체 6채널의 NaN·Inf·절댓값 1e100 초과 유한 극단값 검사
- CH3의 비유한값·극단값 수는 별도 열에 기록. 모델 입력은 계속 CH3 한 채널
- 읽은 원본 바이트의 SHA256 기록 및 검사 전후 크기·수정시간 비교

읽기 성공 4,870개는 모두 float64 `(6, 65536)`, 25,600Hz였습니다.
문제 후보는 값 이상(suspect_values) 100개와 읽기 오류 1개입니다.
읽기 성공 파일 중 NaN 포함 파일은 33개, Inf 포함 파일은 0개,
유한 극단값 포함 파일은 98개입니다. NaN과 극단값이 함께 있는 파일이 있으므로 단순 합산하지 않습니다.
CH3 자체에 비유한값 또는 극단값이 있는 파일은 86개입니다.
CH3만 정상이어도 다른 채널에 문제가 있으면 기존의 보수적인 전체 원본 품질 정책에 따라 제외 후보로 기록합니다.

읽기 오류 파일:

```text

```

검사 전후 크기·수정시간은 4,871개 모두 같았습니다.
읽은 바이트의 SHA256이 완전히 같은 중복 파일 그룹은 없었습니다.
이 검사는 물리적 센서 이상이나 실제 Run의 독립성을 증명하지 않습니다.

## Run 확정에 필요한 근거

기본 정상 상태는 날짜×RPM×Normal1/Normal2로 구분되는 **18개 측정 묶음**입니다.
Normal3까지 포함하면 정상 폴더는 24개입니다. 이는 독립 Run 수를 확정한 결과가 아닙니다.

다음 기록을 데이터 제공자에게 확인해야 합니다.

1. 각 묶음의 실제 운전 시작·정지·재시작 기록과 취득 시스템의 Run 식별 기준
2. RPM 변경 때 운전을 계속했는지, 같은 물리적 Run이 여러 RPM에 걸쳤는지
3. 날짜 사이 재조립·센서 재설치·베어링 교체 등 시험 조건 변경 이력
4. Normal1·Normal2·Normal3의 취득 순서와 의미, 특히 결함 모사 전후 정상 복구 여부
5. 파일별 측정이 연속 기록인지와 파일 간 중첩 여부

파일명 시각과 폴더별 시간 범위는 참고 자료이며 Run ID를 자동 확정하는 근거로 사용하지 않았습니다.
Run을 확정하기 전까지 AE·OCSVM·IF의 실제 학습·최종 평가 차단을 유지합니다.
