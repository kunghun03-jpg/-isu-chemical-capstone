# SQLite 분석 이력

사용자가 직접 확인한 저장·중복 방지·재실행·필터·CSV 결과와 실제 DB 사례는 [2026-11-06 수동 확인 기록](WEB_MANUAL_CHECK_20261106.md)에 구분해 기록했습니다.

실행 명령은 그대로입니다.

```powershell
& "C:\Users\82106\anaconda3\python.exe" -m streamlit run streamlit_app.py
```

## 사용 방법

1. MAT 업로드 후 분석을 실행합니다. 분석만으로 DB에 결과가 저장되지는 않습니다.
2. 결과 아래 **결과 저장**을 누릅니다. 저장 성공 시 분석 ID가 표시됩니다.
3. 화면 아래 **분석 이력**에서 시작·종료 날짜, RPM, 모델, 판정으로 검색합니다. 업로드 없이도 조회할 수 있습니다.
4. 분석 ID를 선택하면 해당 건의 정보와 **모든 저장 모델 결과**를 상세 조회합니다.
5. **검색 결과 CSV 다운로드**로 현재 필터에 맞는 모델 결과를 내보냅니다.

날짜는 분석 시각의 한국 시간(KST) 날짜이며 양 끝 날짜를 포함합니다. 빈 날짜는 제한 없음입니다.
모델과 판정 필터는 동일한 모델 결과 행에 함께 적용합니다. 예를 들어 OCSVM·이상은 OCSVM이 이상으로 판정한 행만 검색합니다.
상세 조회는 그 분석 건에 연결된 다른 모델도 모두 표시합니다.
CSV는 모델 결과별 한 행이며 `analysis_id`로 같은 분석을 묶습니다. 파일명이 수식으로 해석되지 않도록 CSV 문자열은 보호 처리합니다.

## 저장 위치와 내용

기본 DB: **`outputs/history/analyses.sqlite3`**.
앱을 종료해도 이 파일이 남아 있으면 다시 실행했을 때 같은 이력을 읽습니다.
다른 DB 경로가 필요한 경우 실행 환경의 `ISU_CHEMICAL_HISTORY_DB`로 지정할 수 있습니다. 화면에서는 DB 경로를 입력받지 않습니다.
DB를 지우면 이력이 사라지므로 기존 실험과 별도로 보존해야 합니다. 복사 백업은 앱을 종료한 뒤 수행하세요.

| 테이블 | 주요 내용 |
| --- | --- |
| analyses | 분석 ID·중복 방지 키, 분석 UTC 시각·KST 날짜, 저장 UTC 시각, 파일명·SHA256, RPM, 채널, 번들 식별값·출처 실험 |
| model_results | 분석 ID 외래키, 모델명, 모델 버전, 파일 점수, 저장 파일 임계값, 정상/이상 판정 |

모델 버전은 배포용 임의 번호 대신 **해당 저장 모델 파일의 SHA256**(`sha256:...`)입니다. 동일 모델명이라도 가중치·모델 파일이 달라지면 구분됩니다.
번들 ID는 모델·정규화·전처리 명세·임계값을 묶은 기존 패키지 식별값으로 별도 보존합니다.
파일 SHA256은 원본을 식별하는 문자열만 저장합니다. 원본 MAT·파형·업로드 bytes는 DB와 서버 디스크에 저장하지 않습니다.

## 중복과 실패 처리

분석 UTC 시각, 입력 식별 정보, 번들, 모델별 버전·점수·임계값·판정을 정규화해 중복 방지 키를 생성합니다.
저장 클릭 시각을 키에 넣지 않으므로 동일 결과의 재클릭·재전송은 기존 분석 ID를 반환합니다.
DB의 UNIQUE 제약이 여러 요청의 동시 저장도 방지합니다. 세 모델을 저장하는 트랜잭션이 실패하면 부모와 자식 모두 롤백합니다.
SQLite 연결은 요청별로 열고 닫으며 연결 초기화 실패 때도 닫습니다.

브라우저 새로고침은 자동 저장을 실행하지 않습니다. 같은 파일을 **분석 실행**으로 다시 분석하면 분석 시각이 바뀌므로 의도한 새 분석 건으로 취급합니다.
저장 실패 시 완료 표시를 하지 않으며 권한·디스크·잠금 확인 메시지를 안내합니다. 오류 후 재시도할 수 있습니다.
검색·상세 읽기 실패도 화면에 안내합니다. 검색 조건은 SQL 매개변수로 전달합니다.

## 변경과 검증

2026-11-06 검증 결과: **전체 35개 테스트 통과**, 이 중 신규 이력 테스트 4개가 모두 통과했습니다.
동시 저장 8회는 분석 1건·모델 결과 3개로 유지됐고, 재실행한 독립 Python 프로세스에서도 동일 ID와 3개 모델 결과를 읽었습니다.
새 Streamlit 앱 세션에서도 업로드 없이 저장 이력을 조회했습니다.
기존 웹 테스트에서 세 RPM의 전체·개별 모델 점수와 판정이 CLI와 계속 일치했습니다.
기존 실험·추론 패키지 **336개 파일의 SHA256 변경 없음**을 재확인했습니다.
검사는 임시 DB만 사용했으므로 실제 이력에 테스트 데이터가 들어가지 않습니다. 기본 DB는 앱 실행 후 자동 생성됩니다.

- 신규: `vibration/history.py`(저장·검색·상세·CSV), `vibration/history_ui.py`(저장/이력 화면), `tests/test_history.py`.
- 수정: `streamlit_app.py`에 저장 모델 파일 버전 수집·저장 버튼·이력 영역을 연결했습니다. 기존 UI 형태와 추론 호출은 유지합니다.
- 기존 웹 테스트는 임시 DB를 사용하도록 격리했습니다. 실제 이력 DB에 테스트 분석을 쓰지 않습니다.
- 모델·전처리·정규화·임계값·CLI는 변경하지 않았습니다. 기존 모델을 읽기만 합니다.

검사 명령:

```powershell
python -m unittest tests.test_history -v
python -m unittest discover -s tests -v
```

신규 4개 테스트는 다음을 확인합니다.

1. 전체 모델 연결, 같은 결과 중복 차단, KST 날짜·RPM·모델·판정 검색, 상세, CSV와 문자열 보호.
2. 모델 결과 저장 실패 시 부모까지 롤백, 동시 요청 8개 중 신규 저장은 1건.
3. 서로 다른 Python 프로세스에서 동일 DB를 다시 열었을 때 이력 유지와 중복 차단.
4. 실제 Streamlit 저장 버튼 재클릭·rerun, 새 앱 세션의 업로드 없는 이력 조회, 필터·전체 상세와 저장 실패 안내.

SQLite 저장은 분석 성능을 개선하지 않습니다. 기존 [성능 한계](INFERENCE_LIMITATIONS.md)가 그대로 적용됩니다.
결함 후보 추정과 DAE는 이번 범위에 포함하지 않습니다.
