# 사용자 중심 진동 점검 대시보드 V2

기존 streamlit_app.py와 모델·전처리·번들·DB 코드는 유지합니다.
새 진입점은 streamlit_app_v2.py이며 모델 선택 메뉴를 기본 화면에 노출하지 않습니다.
웹에서 실제 추론이 확인됐다는 사용자 보고를 바탕으로 AE를 임시 기본값으로 사용합니다.
AE가 최종 선정됐거나 다른 모델보다 우수하다는 의미는 아닙니다.

## 실행과 설정

프로젝트 루트에서 기존 웹 전용 환경으로 실행합니다.

```bash
"$HOME/capstone-web-venv/bin/python" -m streamlit run streamlit_app_v2.py
```

관리자 환경변수만으로 대표 분석기를 바꿀 수 있습니다.

- ISU_CHEMICAL_V2_MODEL: autoencoder(기본), ocsvm, iforest만 허용
- ISU_CHEMICAL_V2_BUNDLE_ROOT: 기본 outputs/inference_bundles/date_prelim_20261106
- ISU_CHEMICAL_HISTORY_DB: 기존 앱과 같은 SQLite 경로 설정. 기본 outputs/history/analyses.sqlite3

예: `ISU_CHEMICAL_V2_MODEL=iforest .../bin/python -m streamlit run streamlit_app_v2.py`.
DAE 설정은 거부하며 fallback으로 판정하지 않습니다. 기존 앱의 선택 메뉴·설정은 변경하지 않습니다.

## 사용자 흐름

1. 대시보드에서 MAT 업로드, 측정 RPM 선택, 입력 형식 확인
2. 분석 실행 후 정상/이상·파일 점수·저장 판정 기준 확인
3. CH3 시간 파형과 주파수 스펙트럼 확인
4. 필요할 때 구간별 근거와 분석기 정보를 펼쳐 확인
5. 명시적으로 결과 저장 또는 JSON 다운로드
6. 분석 이력에서 날짜·RPM·판정으로 조회, 상세 확인, CSV 다운로드

기본 화면에는 모델 선택이 없으며, 분석기 이름/버전은 접힌 추적 정보에만 있습니다.
설비 수·가동률·실시간 센서 상태 등 없는 데이터를 만들어 표시하지 않습니다.
상단 건수는 실제 DB의 저장 기록으로 계산합니다. 업로드 파일 기반 결과이며 실시간 감시가 아닙니다.

전처리와 추론은 기존 preview_mat 및 SavedModelInference를 사용합니다.
8구간 평균·정규화·threshold·판정 규칙은 그대로입니다. 시각화는 기존 spectrum_frame과
segment_frame을 재사용합니다. 센서 단위·고장 원인은 임의로 확정하지 않습니다.
현재의 높은 정상 오탐률과 대표 분석기 미확정 상태를 화면에 표시합니다.

파일/RPM/분석기/번들 식별 정보가 바뀌면 이전 결과·저장용 버전을 지웁니다.
모델 파일이 없으면 분석을 비활성화하고, 해시·버전·MAT 오류는 판정 없이 안내합니다.
원본 MAT는 저장하지 않으며 기존 로더의 무결성 검사를 우회하지 않습니다.

## 기존 이력 호환

동일 HistoryStore.save/search/detail과 history_csv를 사용하고 SQL 스키마를 추가/변경하지 않습니다.
신규 결과는 기존 모델 이름과 가중치 SHA256, 실제 번들 ID를 그대로 저장합니다.
같은 결과를 다시 저장하면 기존 UNIQUE 키로 중복을 방지합니다.

기존 앱에서 세 모델을 함께 저장한 기록은 하나의 분석 건으로 묶어 표시하고,
어느 모델이든 이상이면 ‘이상 포함’으로 요약합니다. 정상 필터가 일부 모델 행만 골라서
이상 기록을 정상으로 보이게 하지 않도록 전체 결과를 그룹화한 뒤 필터링합니다.
점수가 서로 다른 모델의 이력은 합산/평균하지 않습니다. 접힌 상세 화면은 원래 모델별
판정·점수·임계값·버전을 보존하며 다른 모델끼리 점수 크기를 비교하지 않도록 안내합니다.

## 검증 범위

`python -m unittest tests.test_dashboard_v2 -v`

합성 MAT·테스트 가중치로 기본 화면, 설정 교체, 세 모델의 원래 API와 수치 일치,
저장 중복 방지·기존 다중모델 이력 조회·스키마 동일성, 잘못된 입력·준비되지 않은 번들,
DAE 설정 차단, 기존 V1의 세 모델 결과 회귀를 검사합니다.
Chromium에서도 합성 파일 업로드→분석→저장 흐름을 확인했습니다.
실제 WSL 모델·MAT에 접근한 것이 아니므로 실제 설비 성능/운영 적합성을 검증한 것은 아닙니다.
