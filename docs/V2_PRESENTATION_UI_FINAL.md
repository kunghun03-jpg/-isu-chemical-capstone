# 중간발표 V2 UI 최종 점검

기존 네이비 사이드바·밝은 카드 대시보드 레이아웃을 유지한다. 제목은 `2. 결함 후보 분석`이며 현재 기준 코드에는 잘못된 제목이 존재하지 않았다. 이전 배포에서 다른 문구가 보이면 실행 중인 Git 브랜치·파일과 Streamlit 재시작 여부를 확인한다.

## 상태와 표시

- 원형 표시는 저장된 AE `predicted_anomaly`로 대기/정상/이상을 결정한다. 점수나 RF 결과로 판정을 재계산하지 않는다. 접근성용 상태 레이블도 동일하다.
- 상단은 AE 파일 없음/파일 확인 후 분석 대기/실제 분석 완료/분석 실패를 구분한다. 파일 존재만으로 로딩 성공이나 전체 시스템 정상이라고 표현하지 않는다. 분석 중에는 기존 spinner를 표시한다.
- 입력·RPM 변경 시 이전 결과 및 실패 상태를 초기화한다.
- 모델 참고 예측과 최종 결함 후보는 기존 독립 컴포넌트로 분리한다. 기존 보류 사유를 표시하며 RF 막대 축에는 `RF 모델 점수 · 미보정`을 명시한다.
- 보조 글자 13px, 짙은 회청색, 그래프 축 레이블/제목 크기 개선 및 키보드 포커스 표시를 적용한다. 기존 카드 배치·간격 구조와 하단 요약·저장·이력 동작을 유지한다.

## 검증

합성 데이터와 기존 합성 RF 아티팩트로 자동 테스트 38개가 통과했다. RF.fit을 금지하며 재학습하지 않는다. 대기/정상/이상 원형 일치, 분석 실패 표시/입력 변경 초기화, AE 결과 불변, RF 원시/최종 보류 분리, 저장/이력 및 과거 기록 호환을 확인한다.

Chromium의 1920×1080 및 1366×768에서 합성 MAT 업로드 → AE 이상 → RF Bearing 참고 예측 → 최종 불명확 → 저장 → 이력 재조회를 확인했다. 가로 넘침과 페이지/콘솔 오류는 없었다. 참고 이미지의 네이비/밝은 카드/3열 배치를 유지하되 긴 보류 사유를 숨기지 않아 1366×768에서는 그래프와 하단 요약에 세로 스크롤이 필요하다. 이는 전체 화면 하나에 모든 결과가 들어간다는 의미가 아니다.

사용자 실제 MAT·RF 학습 모델은 이 환경에 없어 실데이터 검증을 수행하지 않았다. 합성 화면의 점수와 모델 결과는 테스트용이며 발표 성능 근거가 아니다.

## WSL 실행

기존 서버를 종료한 뒤 실제 Git 저장소에서 실행한다. 기존 미커밋 작업을 강제 덮어쓰지 않는다.

```bash
git fetch origin
git switch --track origin/feat/v2-presentation-ui-final
# 로컬 브랜치가 이미 있으면 git switch feat/v2-presentation-ui-final
export ISU_CHEMICAL_V2_MODEL=autoencoder
export ISU_CHEMICAL_CANDIDATE_LABELS=0
# 기존 AE 번들·RF 번들·DB 환경 변수 경로를 유지한다.
: "${ISU_CHEMICAL_CANDIDATE_BUNDLE:?기존 RF 번들 경로를 설정하세요}"
"$HOME/capstone-web-venv/bin/python" -B -m streamlit run streamlit_app_v2.py --server.port 8501
```

이 브랜치는 `feat/rf-raw-final-separation`의 커밋을 포함한다. 해당 변경이 main에 없다면 PR에도 함께 포함된다.

## 병합 전 실제 데이터 점검

1. 1920×1080 및 1366×768에서 분석 전 원형 대기를 확인한다.
2. 기존 점수가 확인된 실제 MAT로 AE 점수·임계값·판정과 원형 정상/이상이 동일한지 확인한다.
3. 동일 RF 번들의 실제 OR 파일을 해당 RPM으로 분석한다. AE 이상일 때만 RF를 실행하며 실제 Bearing 예측이 나오면 참고 예측에 표시한다. labels=0에서는 최종 불명확과 실제 보류 사유를 확인한다.
4. 정상 파일에서는 RF 생략을 확인한다. Normal1/2, IR/OR/Roller, Unbalance 및 Looseness와 다른 날짜·RPM도 확인한다.
5. 실제 특징값·파형·FFT·미보정 RF 모델 점수 표기를 확인하고 하단으로 스크롤해 요약/저장 버튼에 접근한다.
6. 저장 후 이력과 앱 재시작 후 재조회에서 AE·원시 예측·최종 후보·사유가 동일한지 확인한다. 기존 기록도 확인한다.
7. 잘못된 입력/모델 경로에서 오류가 숨겨지지 않는지 확인한다. 진단 성능이 충분하다고 주장하거나 Test 결과로 정책을 변경하지 않는다.
