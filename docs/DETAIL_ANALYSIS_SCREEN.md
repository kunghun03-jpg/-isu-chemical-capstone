# 스펙트럼·8구간 상세 화면

구현일: **2026-11-10**. 11/18 목표 기능을 기존 분석 결과·저장 버튼 아래에 추가했습니다.
모델·FFT·정규화·임계값·파일 평균 판정은 변경하지 않았고 재학습하지 않았습니다. DAE는 제외합니다.

## 구현 전 확인

900·1200·1800RPM의 세 모델 모두 필요한 값이 있습니다. **누락된 모델·값은 없습니다.**

| 항목 | AE | OCSVM·IF |
| --- | --- | --- |
| 구간 점수 8개, ID 0–7 | 기존 추론 결과 `segments` | 동일 |
| 저장 구간 임계값 | 추론 `segment_threshold`, 번들 manifest, 원래 threshold JSON | 추론·manifest·원래 joblib의 segment 임계값 |
| 파일 요약 | `file_score`, `file_threshold`, `predicted_anomaly` | 동일 |

세 RPM·세 모델의 저장 설정과 실제 반환 구간 임계값이 정확히 일치했습니다.
900RPM의 구간 임계값 / 파일 임계값은 다음과 같습니다.

| 모델 | 구간 임계값 | 파일 임계값 |
| --- | ---: | ---: |
| AE | 0.33143739054219284 | 0.3242139731159553 |
| OCSVM | -0.3040815614748258 | -0.374341455957232 |
| IF | 0.48041123685402864 | 0.4764751544686325 |

구간 점수는 현재 파일을 기존 저장 모델로 추론해 얻습니다. SQLite의 과거 이력은 파일 점수만 보관하므로 이번 화면은 과거 이력이 아닌 **현재 업로드·분석한 파일**의 상세입니다.
누락된 값은 경고하고, 파일 임계값으로 대체하거나 Q95를 다시 계산하지 않습니다.

## 화면의 값

- 스펙트럼은 미리보기에서 계산하던 기존 `ch3_log_spectra` 결과 `(8,1,3201)`을 재사용합니다. 별도의 FFT 공식을 추가하지 않았습니다.
- 가로축: 0–10,000Hz, 3.125Hz 간격. 세로축: **Hann FFT 단측 진폭 보정 후 log1p(진폭)**. 원래 진폭이나 Train Z-score 값이 아닙니다.
- 대표선은 **8개 log1p 스펙트럼의 평균**입니다. 평균 진폭의 log1p와 구분합니다. 펼침 영역에서 구간별 8개 스펙트럼도 표시합니다. 센서 물리 단위는 임의 확정하지 않습니다.
- 모델별 그래프는 기존 `segments` 점수 8개와 **빨간 점선의 저장 구간 임계값**을 표시합니다. 점 위에서 점수·구간 시간·임계값을 확인할 수 있습니다.
- 화면 구간 1–8은 segment_id 0–7에 대응하며 각 0.32초입니다.
- 모델 아래 파일 요약은 기존 **8구간 평균 점수·저장 파일 임계값·판정**을 그대로 표시합니다. 일부 구간의 초과로 파일 판정을 바꾸지 않습니다.
- 기존 추론 API·CLI·SQLite 저장 형식은 유지합니다. 스펙트럼·원본 업로드는 디스크나 DB에 추가 저장하지 않습니다.

## 확인 사례와 방법

원본 경로·상태·RPM은 [기존 수동 확인 기록](WEB_MANUAL_CHECK_20261106.md)의 데이터 목록·SHA256 대조를 기준으로 했습니다.

| 파일 | 원본 상태 / RPM | AE·OCSVM·IF 파일 판정 |
| --- | --- | --- |
| 20260912_133556_Vib.mat | 9/12 Normal1 / 900 | 모두 정상 |
| 20260912_170916_Vib.mat | 9/12 Looseness0.1 / 900 | 모두 정상: 미탐 의심 유지 |
| 20260919_152236_Vib.mat | 9/19 원본 Looeness0.1 → 통일 Looseness0.1 / 900 | 모두 이상 |

특히 9/12 결함 라벨 파일의 IF는 **구간 3(segment_id 2)만 초과**합니다.
해당 점수 약 0.491553110779 > 구간 임계값 약 0.480411236854이나,
파일 평균 약 0.470360658143 < 파일 임계값 약 0.476475154469이므로 파일은 기존대로 **정상**입니다.
이번 화면이 미탐을 해결한 것은 아닙니다. 높은 정상 오탐률·실제 Run 미확정도 미해결 상태입니다.

기존 앱이 실행 중이면 터미널에서 Ctrl+C로 종료한 뒤 프로젝트 폴더에서 다시 실행합니다.
현재 파일 감시가 꺼져 있어 실행 중인 서버에는 코드 변경이 자동 반영되지 않을 수 있습니다. 저장 이력은 기존 DB에 유지됩니다.

```powershell
& "C:\Users\82106\anaconda3\python.exe" -m streamlit run streamlit_app.py
```

1. 위 파일을 업로드하고 900RPM·전체로 분석합니다.
2. **상세 분석**에서 log1p 스펙트럼과 모델별 구간 그래프를 확인합니다.
3. 위 임계값 표·파일 요약과 비교하고, 9/12 파일의 IF 구간 1개 초과와 파일 정상 판정이 함께 표시되는지 확인합니다.
4. JSON 다운로드의 `segments`, `segment_threshold`, `file_score`, `file_threshold`, `predicted_anomaly`와 대조할 수 있습니다.

CLI 예시:

```powershell
python -m scripts.infer_mat --file "data/20260912/20260912_900RPM/Looseness0.1/Vib/20260912_170916_Vib.mat" --rpm 900 --model all
```

신규 `vibration/detail_ui.py`는 그래프 데이터 검증·표시를 담당합니다. `vibration/web_inference.py`는 기존 FFT 결과·주파수를 반환하고 `streamlit_app.py`는 결과 아래 상세를 호출합니다. Altair를 requirements에 명시했습니다.
`tests/test_detail_ui.py`는 기존 전처리와 스펙트럼의 원소별 일치, 누락 거부, 위 세 파일의 Streamlit 화면 흐름·차트 생성·CLI 일치를 검사합니다.
자동 화면 검사는 Streamlit AppTest에 업로드를 주입하는 방식입니다. 새 사용자 수동 브라우저 확인이나 새 성능 시험을 수행했다고 해석하지 않습니다.

## 2026-11-10 검증 결과

- 전체 회귀 테스트 **37개 통과**(기존 35개 + 상세 화면 2개).
- 위 세 파일 × 세 모델의 파일 점수·파일 임계값·판정 및 8구간 점수·구간 임계값이 기존 CLI와 **정확히 일치**했습니다. 점수 차이는 0입니다.
- 전체 모델 분석 화면에 파형 1개·스펙트럼 2개(대표/구간별)·모델 구간 그래프 3개가 생성되는지 확인했습니다. 개별 모델 선택과 SQLite 저장·검색·중복 방지 회귀 검사도 통과했습니다.
- 표시 스펙트럼과 기존 추론 전처리 결과는 원소별로 완전히 일치했습니다. 8구간 평균과 파일 점수의 일치, 임계값 누락 시 대체하지 않고 거부하는 동작도 확인했습니다.
- 기존 실험·추론 패키지 336개 파일의 SHA256 변경 없음과 세 사례 원본 SHA256의 기존 기록 일치를 확인했습니다. 실제 이력 DB에는 테스트 결과를 쓰지 않았습니다.
